# Interface audit — 2026-10-04

## Result and scope

The inspected interfaces pass the visual and interaction checks below after iteration. Native window checks used a 1280×720 viewport at 150% UI scale. Renderer fixtures additionally exercise 100% and 150% scale. This is acceptance of those checked configurations, not a claim that every resolution or gameplay state was exercised.

Most fixes are already in `c305f1e` (committed during the investigation). The final working-tree changes add failed-load feedback and a useful mixed-selection summary, plus their validation updates. No commit was created by this audit.

## Inspection, changes, and verification

| Interface | Problem addressed | Verification |
| --- | --- | --- |
| Shared layouts | RmlUi lacked browser-style default block flow; transparent texture margins wasted panel space. | Explicit block flow and cropped panel sprite inspected across menus and HUD. |

| Settings | Long columns could shrink or hide controls. | Scrolled both columns through audio and bindings; fixed footer stays accessible; cancelled edits. |

| Editor | Oversized frame margins, truncated names and inaccessible palette rows. | All 11 two-line labels and bottom row accessible; palette scrolling does not zoom terrain. |
| Gameplay toolbar/minimap | Crowding and frame overlap. | Readable resource values and buttons; minimap clears the toolbar. |
| Entity HUD | Excess blank space, clipped statistics and unstable scrolling during updates. | Split action/info panels, readable bars, all statistics/actions reachable; value updates retain scroll and selection changes reset it. |

## Validation

- Full Debug build succeeded: `cmake --build build/debug --config Debug -j 8`.
- Focused final tests passed: `entity_hud_model`, `renderer_integration`, `render_architecture`, `state_stack_transitions`.
- `git diff --check` passed (Git emits line-ending conversion warnings).
- Full-suite rerun: `ctest --test-dir build/debug -C Debug --output-on-failure -j 4`: **18/19 passed**, 99.80 seconds. All UI-related tests passed; only `game_systems` failed.

The known non-UI failure is `game_systems`: “Unable to place player 2 in its assigned corner after 256 attempts (selection seed 1592594996)”. It reproduces independently. The relevant generation implementation/test files are unchanged from `6db4eaf`; the test does not use the UI renderer. The seed or generation algorithm was not changed to conceal this failure. Whole-game validation therefore does not receive an unconditional OK.

## Limits and preserved state

Successful loading of the existing local save could not be checked because it is incompatible; the failure path was checked instead. Other resolutions, languages and every possible queue/entity combination remain outside this visual sample. Renderer screenshots under `build/ui-audit` are test fixtures, not recordings of every live screen.

No map or game was saved, and no settings were applied during the audit. The runtime match-setup profile is left intact, including the current seed 123123. Unrelated user changes are preserved. The verification game was closed after the final live check.
